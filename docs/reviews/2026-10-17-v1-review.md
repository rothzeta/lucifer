# Lucifer repository review and path to v1

**Reviewed:** 17 October 2026  
**Repository:** [rothzeta/lucifer](https://github.com/rothzeta/lucifer)  
**Baseline:** [f49202a22613ff87320568ab0fe55fe90012de21](https://github.com/rothzeta/lucifer/commit/f49202a22613ff87320568ab0fe55fe90012de21)

## Assessment

Lucifer already contains the central software path for an NFC album player. It uses direct C# PN532 access, reads a self-describing NDEF identity, resolves a configured album to Navidrome tracks, orders them, and sends them to a persistent mpv process.

A small usable v1 is plausible after a bounded completion effort if the physical path already works on the Pi. The source alone does not establish that result. The missing work concerns programming and registering albums, reliable state transitions, protocol handling, controls, and device delivery.

The repository has one application project targeting .NET 10 with Iot.Device.Bindings 4.2.0. The player is in `Amp.Nfc/Program.cs`. A separate writer is at the root. The original README is empty. No checked-in test project or deployment assets were present in the reviewed tree.

## Recovered design

Earlier discussions identify the first device as Pi 3B, PN532 V3 through CH341 USB-to-TTL, Navidrome, mpv, and FiiO K5 Pro. The later 28 August direction keeps the implementation in C# with direct NDEF read/write and a persistent player process. An earlier C#/F# proposal does not override that later direction.

The 17 August physical concept uses a standard ceramic NFC ring as the record and a distinct album case or artwork. Elaborate reliefs, pyramids, and sculptures were longer-term possibilities. Display choices and the final enclosure were still unsettled. KB1K appeared in the controller discussions. Future play counts were part of the interest in direct tag read/write.

The design rationale favoured exact MusicBrainz release identities. The code now uses `amp:album:1:mbid:<UUID>`. Retain that working namespace. A release represents an edition; a release group collects related editions. The current Mastodon UUID resolves to the 15th anniversary deluxe release. [MusicBrainz release](https://musicbrainz.org/doc/Release), [release group](https://musicbrainz.org/doc/Release_Group), [configured Mastodon release](https://musicbrainz.org/release/a24495e4-eb70-48cd-b0fa-31a606459d26).

The repository's continue-on-removal behaviour is retained as a proposed v1 policy. Retrieved history did not establish an explicit user decision about removal. The [blackboard](../../BLACKBOARD.md) labels proposed completion policies separately from recovered direction.

## What to retain

- One small application with direct hardware integration.
- One PN532 owner and one persistent mpv process.
- A tag that contains album identity rather than only a reader UID.
- Navidrome as the music source and mpv as local playback.
- Immutable values for identity and tracks.
- Disc/track ordering for complete metadata.
- Provider credentials outside source code.
- Ordinary focused classes instead of an extensive architectural framework.

The existing awaited replace-then-append commands are ordered. Per-command socket connections are not automatically a defect. The selected authentication follows the Subsonic protocol; its MD5 token step is not a reason to invent replacement authentication.

## Findings

### R01 A failed first attempt suppresses the present tag

**Release blocker.** [Player lines 69–128](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L69-L128).

The program assigns `currentUid` before NDEF reading, catalogue lookup, HTTP, or playback. If any transient step fails, the next observation of the same UID is ignored. The selected object can stay on the reader without another attempt.

Separate observed presence, attempt state, and successful playback. Retry transient failures while suppressing repeated permanent rejection. Moving the assignment alone is insufficient because invalid tags would then cause repeated work. **Task: LUC-04.**

### R02 One uncertain detection rearms the same album

**Release blocker.** [Player lines 53–75](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L53-L75).

Every null detection clears `currentUid`. The next successful read can restart the same album. In the pinned binding, `ListPassiveTarget` returns null for no target and for failed command/response operations. One null is not reliable evidence of removal.

Confirm absence over a measured interval. Preserve state on identified faults. The binding's `ReselectAfterError` reselects after a failed operation but returns the original failed result; it does not supply the application's retry policy. [PN532 4.2.0](https://github.com/dotnet/iot/blob/v4.2.0/src/devices/Pn532/Pn532.cs#L515-L557), [Ultralight 4.2.0](https://github.com/dotnet/iot/blob/v4.2.0/src/devices/Card/Ultralight/UltralightCard.cs#L265-L329). **Task: LUC-04.**

### R03 mpv events are parsed as replies

**Release blocker.** [Player lines 414–434](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L414-L434).

The command method reads one line and immediately accesses `error`. An unsolicited event can arrive first. A valid command can then appear to fail and stop album queue construction.

Use request IDs, match replies, handle events, and bound the wait. The [mpv IPC specification](https://mpv.io/manual/stable/#json-ipc) explicitly permits unrelated queued events before a command reply. **Task: LUC-05.**

### R04 The writer is source code without an executable delivery path

**Release blocker.** [Root writer](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Program.cs), [only project](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Amp.Nfc.csproj).

The only project is below `Amp.Nfc`; it does not compile the parent writer. The root file has no file-based package directive. Its displayed root `dotnet run -- write` command lacks a project at that location.

Integrate read/write modes into one executable. Validate commands before waiting for a card. **Task: LUC-01.**

### R05 Writer success does not establish the right album data

**Release blocker.** [Writer lines 30–50](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Program.cs#L30-L50), [lines 147–190](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Program.cs#L147-L190).

The writer accepts arbitrary text. Its example payload is rejected by the player. It prints success before reading back and never compares the result with the requested identity.

Share one codec, validate before writing, compare read-back, and return failure on mismatch. The binding already checks capacity when writing; missing library capacity enforcement is not a finding. **Task: LUC-02.**

### R06 Only two albums are registered in compiled code

**V1 function gap.** [Player lines 20–27](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L20-L27).

A correctly programmed third album cannot work without a source edit. Move exact release-to-provider-ID mappings to configuration. This preserves portable tag identity and makes local registration practical.

Automatic import is a later improvement. OpenSubsonic offers paged [getAlbumList2](https://opensubsonic.netlify.app/docs/endpoints/getalbumlist2/) and an optional album [musicBrainzId](https://opensubsonic.netlify.app/docs/responses/albumid3/) field. Check actual server metadata before using it. [getAlbum](https://opensubsonic.netlify.app/docs/endpoints/getalbum/) takes the server album ID. **Task: LUC-03.**

### R07 API failures become property exceptions

**Reliability gap.** [Player lines 206–234](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L206-L234).

After HTTP success the code immediately reads `album`. The API also has an application-level status/error envelope. Authentication or missing-album failures therefore lose their useful cause.

Read the envelope first. Bound network operations. For missing or duplicate positions, specify a deterministic fallback instead of ordering unknown tracks as zero. [OpenSubsonic envelope](https://opensubsonic.netlify.app/docs/responses/subsonic-response/). **Task: LUC-06.**

### R08 Queued tracks are reported as playing

**Reliability gap.** [Player lines 128–130](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L128-L130), [lines 340–355](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L340-L355).

A successful playlist command is not evidence that the stream or DAC works. A later append failure can leave a partial queue. The source's command order is correct; its observable completion and partial-failure policy are incomplete.

Observe loading and playback outcomes. Treat album replacement as one serialized application operation. Keep the current album during preparation and reject stale preparation before mutation. [mpv playlist commands](https://mpv.io/manual/stable/#command-loadfile). **Tasks: LUC-05 and LUC-07.**

### R09 Fatal component failure can leave an inert application

**Device release blocker.** [Player startup calls](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L36-L38), [outer recovery loop](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L136-L139), [startup](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L301-L337).

The reader and mpv are created once. The outer catch repeatedly uses the same instances. IPC has no per-command deadline. Cancellation during mpv startup occurs before ownership reaches the caller's using scope.

Own partial startup, handle service termination, and use an explicit supervisor policy. A whole-service restart on fatal adapter failure is enough for v1. No-tag silence alone must not trigger fatal reader recovery. **Tasks: LUC-05 and LUC-10.**

### R10 Controls are adapter methods with no input route

**Proposed v1 operation gap.** [Player lines 359–381](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L359-L381).

Pause, resume, next, and previous exist, but there are no callers in Lucifer. Inspect the actual controller and wire its events. Define boundary behaviour instead of accidentally inheriting `playlist-prev force`, which can stop at the first track.

Keep the existing DAC volume control. A display can follow later. **Task: LUC-09.**

### R11 Configuration and installation are not reproducible

**Device release blocker.** [Player lines 11–18](https://github.com/rothzeta/lucifer/blob/f49202a22613ff87320568ab0fe55fe90012de21/Amp.Nfc/Program.cs#L11-L18).

Serial, audio, and socket locations are compiled constants. The repository does not supply a service unit or installation procedure. Current explicit cancellation handles Ctrl+C, not a complete service lifecycle.

Provide options, startup diagnostics, service ownership, a runtime directory, and an installed-package test. The target runtime depends on OS bitness: Microsoft documents `linux-arm64` for 64-bit and `linux-arm` for 32-bit. [ARM deployment](https://learn.microsoft.com/en-us/dotnet/iot/deployment). **Tasks: LUC-01, LUC-08, LUC-10, LUC-11.**

### R12 Proof of device readiness is missing

**Release evidence gap.**

No SDK or mpv was installed in the review environment. No compilation, automated tests, NFC operation, real Navidrome request, or DAC playback was executed in this review. Existing source and prior experiments do not establish a reproducible release.

Run the [acceptance cases](../../blackboards/ACCEPTANCE.md) on a candidate package. Test the actual ring placement, full albums, a real disc boundary, controls, reboot, and recovery. **Task: LUC-12.**

## Proportionate implementation

Keep one application project and add one test project. Separate these responsibilities into files as fixes require them:

| Responsibility | Purpose |
| --- | --- |
| Program and options | Commands, construction, configuration, lifetime |
| Album identity and tag codec | Shared parse/format rules |
| PN532 adapter | One owner for discovery and read/write |
| Catalogue | Exact release-to-provider mapping |
| Navidrome source | API outcomes and ordered playable tracks |
| mpv player | Child ownership, IPC, playback observations |
| Controller | Presence, selection, retry, queue replacement, controls |

Use interfaces at hardware and protocol boundaries where tests need substitutes. A database, message broker, event-sourcing system, dynamic plugin registry, new language, or custom audio engine is unnecessary for this release.

## Completion judgement

Budget roughly five to eight focused implementation sessions plus real-device listening and boot/recovery checks if the present hardware chain works. This is a planning estimate, not measured project velocity. LUC-08 should revise it.

The critical sequence is a runnable and verified writer, a configurable catalogue, stable selection and IPC, then installed-device acceptance. Automatic discovery, display design, play-count semantics, and elaborate physical editions can proceed after that gate.
